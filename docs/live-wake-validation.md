## 实测发现并修复的问题

原 `task_start` 同时返回普通 `text` 提示和 `structuredContent`。Codex 在这条路径只展示提示，导致首轮回复“task ID not returned by tool”。自动续跑仍能发生，但模型无法取得任务 ID。

现将提示放进结构化结果的 `message` 字段，交由 SDK 一并渲染任务 ID、状态和日志尾部。修复后在同一个真实 Codex 会话重新执行，首轮准确返回 `f94483bb-b229-4681-ad45-f799ed517c90`，后续自动续跑成功。增加了模型可见结果必须包含任务 ID 的回归断言。

Pi 默认选择的 OpenCode Go 模型因缺少有效订阅返回 403；实际成功验证使用已配置的直连 DeepSeek 模型。未更改用户默认模型或全局审批配置。

修复后类型检查和 26 项测试全部通过；相关受管检查任务为 `d69e9189-785e-478d-9764-adc2b69db72d`。此前侧栏 UI 回归已通过。测试会话和工作区在收尾时归档，完整临时证据保留在 `/tmp/paseo-wake-live-767ezlgw/report.json` 及两个临时工作区中。
